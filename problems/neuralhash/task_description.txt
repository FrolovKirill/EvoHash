**TASK**: Evolve a Python attack strategy that generates hash collisions against Apple NeuralHash.

==============================================================================
BACKGROUND
==============================================================================

NeuralHash is a 96-bit perceptual hash developed by Apple, originally designed
for on-device CSAM detection. Unlike DCT-based hashes (pHash, PDQ), NeuralHash
uses a neural network to extract semantic features.

NeuralHash computation pipeline:
  1. Convert image to RGB, resize to 360x360
  2. Normalise pixel values to [-1, 1]  (arr = arr * 2.0 - 1.0)
  3. Run through a convolutional neural network (ONNX model) -> 128-dim float embedding
  4. Project embedding: seed_matrix (96x128) @ embedding (128,) -> 96 floats
  5. Binarise via sign: bit[i] = 1 if projected[i] >= 0, else 0  -> 96-bit hash

Key properties:
  - The hash is determined by a LEARNED embedding, not hand-crafted transforms
  - The CNN operates on 360x360 RGB -- colour matters (unlike pHash/PDQ)
  - The seed matrix projects 128-dim to 96-dim: small embedding changes can flip
    multiple bits simultaneously (entangled bits)
  - The embedding is a smooth function of pixel values (differentiable in principle),
    but we only have black-box access through hash_fn.compute()
  - Each hash query runs ONNX inference (~5-50ms depending on hardware)

Two images are a **collision** when their Hamming distance <= 17 bits (out of 96).
This means ~18% of bits can differ -- a moderate threshold.

GOAL: minimally perturb a source image so its NeuralHash matches a target hash.

READING THE TARGET HASH:
  target_hash          -> numpy array, shape (96,), dtype uint8, values {0, 1}
  source_hash = hash_fn.compute(source_image)
  source_hash          -> numpy array, shape (96,), dtype uint8, values {0, 1}
  bits_to_flip = source_hash ^ target_hash  -> which bits must change
  You need to flip AT LEAST (current_distance - 17) bits to achieve a collision.

==============================================================================
CRITICAL PITFALLS -- READ BEFORE WRITING ANY ATTACK
==============================================================================

  X DO NOT work in a small spatial domain (32x32, 64x64).
    NeuralHash processes 360x360 RGB images through a CNN. Unlike DCT-based hashes,
    there is no simple downsampled domain. The CNN extracts features at multiple
    scales -- perturbations must survive the full network.

  X DO NOT assume DCT-domain attacks will work.
    NeuralHash is NOT based on DCT. It uses learned convolutional features.
    DCT manipulation may accidentally change the right features, but there is
    no principled mapping from DCT coefficients to hash bits.

  X DO NOT ignore colour channels.
    The CNN processes full RGB input. Grayscale-only perturbations discard 2/3
    of the available attack surface. Perturb all three channels.

  X DO NOT expect hash distance to change smoothly with perturbation magnitude.
    The projection + binarisation creates sharp boundaries. A small change in
    embedding can flip 0 bits or many bits at once. Gradient estimation is
    noisy but MORE useful here than for DCT hashes because the underlying
    embedding is continuous.

  X DO NOT use too many queries.
    Each query requires ONNX inference. Budget queries carefully (~500-2000 max).

==============================================================================
PERFORMANCE METRIC
==============================================================================

  efficiency = ASR / (mean_L2 + e)   <- MAXIMISE THIS

  - ASR (Attack Success Rate): fraction of image pairs where hash_distance <= 17
  - mean_L2: mean normalised L2 distortion = ||d||_2 / sqrt(H*W*C)
  - Higher efficiency = more successful attacks with less visible distortion

==============================================================================
ATTACK STRATEGIES -- RANKED BY EFFECTIVENESS
==============================================================================

NeuralHash is a neural network -- attacks must treat it as a black-box function
from 360x360x3 pixels to 96 bits. The underlying embedding is continuous, which
makes gradient-based methods MORE viable than for DCT hashes.

  *** DECISION-BOUNDARY WALK (most reliable)
    HopSkipJump-style: start from the target image (guaranteed collision),
    binary-search to the decision boundary, then walk the boundary toward
    the source image to reduce L2 distortion.
    Works well because:
    - Only needs binary oracle (collides / does not collide)
    - The collision region (dist <= 17) is a substantial volume in pixel space
    - No need to understand the CNN internals
    Work in the full 224x224x3 space (or resize to 360x360 for hash queries).
    Use >= 100 gradient-estimation samples per step for stable boundary normals.

  *** NES / ANTITHETIC GRADIENT ESTIMATION (effective for NeuralHash)
    Unlike DCT hashes, NeuralHash's embedding changes continuously with pixels.
    NES with antithetic sampling can estimate useful gradients:
    - Use Hamming distance as the loss function
    - sigma ~ 0.01-0.05 (in normalised pixel space)
    - Population size >= 50 (antithetic pairs)
    - Apply momentum (Adam/RMSprop) to accumulate signal across steps
    Key advantage over DCT hashes: the gradient is NOT always zero because
    the underlying embedding shifts smoothly, even when hash bits don't flip.

  ** TRANSFER-BASED PERTURBATION PATTERNS
    Since NeuralHash uses a CNN, adversarial patterns that fool CNNs in general
    (high-frequency textures, patch-based perturbations) can be effective:
    - Try grid patterns, checkerboard textures at various frequencies
    - Spatial perturbations concentrated in semantically important regions
    - Random low-rank perturbations (sum of a few outer products)

  ** RANDOM SEARCH IN SUBSPACE
    Project the search into a lower-dimensional space:
    - Random orthogonal basis of dimension 50-200 in pixel space
    - DCT basis vectors as a structured subspace (not because hash uses DCT,
      but because DCT provides a natural frequency decomposition)
    - Search this subspace with coordinate descent or random sampling

  * HYBRID: BOUNDARY WALK + GRADIENT REFINEMENT
    Start with boundary walk to get a collision, then refine with NES in a
    neighbourhood around the current solution to reduce L2 while maintaining
    the collision. This two-phase approach often gives the best efficiency.
